### 🎉 **Notion Files Management v1.4.0-Status**

这是 **Notion Files Management** 的正式版功能更新，工具箱「Notion 页面信息」升级为「Notion 页面大小自动更新/查询」，新增自动扫描文件大小并写入属性的能力。

------

## ✨ **新功能**

### 📏 **Notion 页面大小自动更新/查询**

- 工具箱「Notion 页面信息」升级为「Notion 页面大小自动更新/查询」
  - 新增「自动更新」模式：扫描数据源中选定页面的所有文件块，通过 HTTP HEAD 请求获取每个文件的实际大小，累加后自动写入用户指定的数字属性（GB，保留 3 位小数）。
  - 双线程池架构：链接查询线程池（默认 3）通过 Notion API 递归查询页面 blocks 并提取文件 URL；大小查询线程池（默认 5）发起 HEAD 请求获取文件大小并更新属性。
  - 全局 Notion API 速率限制器：所有 API 调用共享速率限制（0.34s/请求），确保不超过 3 req/s。
  - 生产者-消费者模型：链接查询线程作为生产者提取文件 URL，大小查询线程作为消费者探测大小并更新属性。
  - 预扫描页面分类：按大小属性是否已设置分为「未设置大小」（默认全选）和「已设置大小」（默认不选），支持全选/反选。
  - 可自定义线程数：链接查询线程（1-8）、大小查询线程（1-16）。
  - 实时进度显示（链接已查询/已更新/失败），综合进度百分比（链接查询 40% + 大小更新 60%），支持取消操作。
  - 页面选择弹窗响应式设计，通过 `ResponsiveClampConverter` 自适应窗口尺寸，确保按钮始终可见。
  - 原有「查询单个页面」功能完全保留，通过选择对话框分流。

------

## 🔧 **技术变更**

### Python 后端

- 新增 `page_size_update.py` 模块（`PageSizeUpdateTask` 类 + `scan_pages_for_size_property` 函数）。
- `PageSizeUpdateTask` 采用双线程池 + 生产者-消费者 + 全局速率限制器架构。
- 递归 block 查询支持自动分页和 4 次指数退避重试。
- `main.py` 新增 `scan_data_source_pages()`、`start_page_size_update()`、`get_page_size_update_progress()`、`cancel_page_size_update()` 共 4 个入口方法。

### C# 前端

- `NotionBackendService` 新增 4 个门面方法和 3 个记录类型（`PageSizeInfo`、`ScanPagesResult`、`PageSizeUpdateProgress`）。
- `ToolsPage` 工具入口变更，新增 4 个模态卡片（选择模式 → 配置 → 页面选择 → 进度），新增约 350 行事件处理代码。
- 页面选择弹窗使用 `ResponsiveClampConverter` 实现响应式尺寸（宽度 60%，高度 85%）。

<a name="english"></a>

### 🎉 **Notion Files Management v1.4.0-Status**

This is a stable release of **Notion Files Management**, upgrading the "Notion Page Info" tool to "Notion Page Size Auto-Update/Query" with the ability to automatically scan file sizes and write them to page properties.

------

## ✨ **New Features**

### 📏 **Notion Page Size Auto-Update/Query**

- Toolbox "Notion Page Info" upgraded to "Notion Page Size Auto-Update/Query"
  - New "Auto-Update" mode: Scans all file blocks in selected pages of a data source, retrieves actual file sizes via HTTP HEAD requests, and automatically writes the cumulative size to a user-specified number property (in GB, 3 decimal places).
  - Dual thread pool architecture: Link query pool (default 3) recursively queries page blocks via Notion API to extract file URLs; Size query pool (default 5) sends HEAD requests to get file sizes and updates properties.
  - Global Notion API rate limiter: All API calls share a single rate limiter (0.34s/request), ensuring compliance with the 3 req/s limit.
  - Producer-consumer model: Link query threads produce file URLs; size query threads consume them to probe sizes and update properties.
  - Page pre-scan classification: Pages are categorized by whether the size property is already set — "Not Set" (selected by default) and "Already Set" (deselected by default), with select all/deselect all support.
  - Customizable thread counts: Link query threads (1-8), size query threads (1-16).
  - Real-time progress display (link queried/updated/failed), combined progress percentage (link query 40% + size update 60%), with cancel support.
  - Responsive page selection dialog using `ResponsiveClampConverter` to adapt to window size, ensuring buttons are always visible.
  - Original "Query Single Page" functionality fully retained, accessible via a mode selection dialog.

------

## 🔧 **Technical Changes**

### Python Backend

- New `page_size_update.py` module (`PageSizeUpdateTask` class + `scan_pages_for_size_property` function).
- `PageSizeUpdateTask` uses dual thread pools + producer-consumer pattern + global rate limiter architecture.
- Recursive block querying with automatic pagination and 4-retry exponential backoff.
- `main.py`: Added `scan_data_source_pages()`, `start_page_size_update()`, `get_page_size_update_progress()`, `cancel_page_size_update()` — 4 new entry methods.

### C# Frontend

- `NotionBackendService`: Added 4 facade methods and 3 record types (`PageSizeInfo`, `ScanPagesResult`, `PageSizeUpdateProgress`).
- `ToolsPage`: Updated tool entry, added 4 modal cards (mode selection → configuration → page selection → progress), ~350 lines of new event handling code.
- Page selection dialog uses `ResponsiveClampConverter` for responsive sizing (width 60%, height 85%).

- `AssemblyVersion`: 1.3.0.0 → 1.4.0.0

## ⚠️ **Known Issues**

- Only supports Windows x64.
- Tasks are not persistent after restarting the program (memory-only storage).
- Breakpoint resume is not supported yet.
- No automatic update feature; updates must be checked manually.
- Data source migration uses title-based matching; pages with identical titles may cause imprecise mapping.
- Notion temporary file URLs expire after ~1 hour; URLs fetched early in large batch updates may become invalid.
